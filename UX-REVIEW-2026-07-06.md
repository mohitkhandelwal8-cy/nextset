# NextSet UX & Feature Review — 2026-07-06 (v68)

Method: full source read of `index.html` (3,097 lines) + `sw.js`, plus a live walkthrough in a headless browser at 375×812 (and 320px overflow check), covering: day-one onboarding → first workout → 4 weeks of seeded history → progression suggestions → insights → history editing → plans → themes. Lenses: brand-new user, week-4 regular, public-launch prospect, casual/non-techy user.

## What's genuinely strong

- **Insights after a single session** is the best first-day payoff I've seen in a tracker: overview tiles, volume trend, consistency grid, muscle map, muscle groups, push/pull/legs balance, and per-lift trends all populate from one workout.
- **"Last time" chips + live volume-vs-last-time bar** in the logger directly serve the app's core promise.
- Cross-gym machine linking, backup/restore, PWA update flow, offline service worker, PR toasts — all correctly built.
- Accessibility basics are unusually good for a solo project: 44px tap targets, aria-labels, focus-visible styles, reduced-motion support.
- No console errors; no horizontal overflow at 320px; light theme is clean.

## Findings

### P0 — trust & data integrity

1. **Ticking a set "done" silently rewrites the next set's reps.** `index.html:1095-1096` pulls the next un-done set up to the just-completed set's weight *and reps* whenever `nxt.weight <= set.weight`. Repro: pre-fill 10/9/8 reps, tick set 1 → set 2 becomes 10. Logged data ends up 10/10/10. The pull-up idea is good for weight, but it must never overwrite values the user explicitly edited (track a `touched` flag per set, or only pull up sets still at their suggested values).
2. **Finish silently drops un-ticked sets.** `finishSession` saves only `done` sets. A user who entered weights/reps but forgot to tick the last checkbox loses it with no warning. Add a guard: "2 sets have reps but aren't ticked — save them / discard them."
3. **"Remove" (exercise) during a workout has no confirm and no undo**, even when the exercise has completed sets — and it sits right next to "Remove set". One mis-tap deletes logged work.

### P1 — core-loop value & launch readiness

4. **No rest timer.** The app computes and displays rest ("2 min rest") but never counts it down. Auto-starting a countdown when a set is ticked is the single biggest feature gap vs Hevy/Strong — table stakes if going public.
5. **Quick Add (natural language) is unreachable.** `openQuickAdd` (`index.html:1849`) is never wired to any button, yet the README headlines it. Wire it into the in-progress Today view, or delete it.
6. **No global weight-unit preference.** Every new exercise defaults to kg; History hardcodes "kg" volume labels. For US/UK users (lb gyms) this is a launch blocker. Add a one-time unit choice in onboarding + a More setting that sets defaults and display units.
7. **Empty-plan "Start workout" is the primary CTA.** On "Ready to start" with 0 exercises, the orange button leads to an empty logging state; the useful action (Add exercises) is secondary. Swap emphasis until the plan has ≥1 exercise.
8. **Progression note copy is jargon for casual users.** "Target +4% volume — ~798 vs 743 last time (+7%). Same weights, +reps." Unitless tonnage numbers mean nothing to a non-data-nerd, and "+4% target" next to "(+7%)" reads as a contradiction. Say what to do, not the math: "Beat last time: same weights, one extra rep on your first set."
9. **Search relevance:** own-collection weak matches outrank exact library matches. Typing "leg press" showed *Dumbbell Bench Press* (matches only "press") above *Leg Press*. Rank across both groups by match strength, or require ≥2-token matches to surface own exercises first.
10. **Suggested set order looks wrong.** The volume solver outputs e.g. 10 / 9 / 10 reps (unsorted after rep additions). Sort the plan before display — users read 10/9/10 as a bug.

### P2 — polish & scale

11. **Logging screen density:** every non-current exercise card renders fully expanded (~10 buttons each — RPE row, joint toggle, 5 action buttons, all sets). A 6-exercise workout is an enormous scroll. Collapse not-yet-started exercises to compact rows (name + target), expanding on tap.
12. **No elapsed-workout timer** and no in-progress indicator on other tabs — wander to Insights mid-workout and nothing says a session is running.
13. **Pre-start preview hides the plan's targets.** Rows show only "3×8–12 · 2 min rest"; suggested weights and ↑/→ progression pills appear only after starting. Show them in the preview — that's the moment users decide.
14. **Picker "Done" button confusion:** in Add exercise, an orange "Done" primary sits above the list before anything is added, and duplicates the ✕ close. Make it a subtle "Close" (or show "Done · 3 added").
15. **Copy nits:** "1 days in 2026" (Consistency); "Joint flagged on X ×6" counts sets, not workouts (2 flagged sessions read as ×6).
16. **Sheets don't close on Escape** (keyboard/desktop PWA users).
17. **Dead code:** `autofillPlanFromHistory` (empty stub), `renamePlan` (unused — rename is inline in the editor), `notes` field on exercises has no UI.
18. **No demo/sample mode.** A public-launch prospect evaluating against Hevy sees an empty app; the wow surface (Insights) only lights up after logging. Consider a "See it with sample data" toggle on onboarding.
